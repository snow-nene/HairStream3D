# 左侧缺口矛盾的主因

## 结论

左侧缺口不是单纯的头发 mesh 缺面，也不是左相机左右方向颠倒。主因是**跨视角观测没有 3D 对应关系，并叠加 front 标定与头模坐标不完全一致**：

1. front 使用原始照片及其 front strand map，属于唯一真值。
2. left 使用 Blender 侧视渲染作为 FLUX 输入，再从 FLUX 图像重新生成 seg、strand 和 depth；这些像素是生成先验，不是原始照片中同一表面点的观测。
3. 补根时把 left 的“头发像素”反投影到头模，再用 front 原图做严格语义守卫。于是同一候选根在 left 被标成头发、在 front 投影后却落到非头发区域，候选被拒绝，形成可见缺口。

## 已排除的原因

`blender_renders/camera_params` 中 front、left、right、back 的相机轴是规则的正交旋转：left 相对 front 为约 90°，right 为约 -90°，四视角 `ortho_scale` 均为 1.322667。没有发现 left 特有的尺度或方向错误。

但这只能排除 Blender 四视图内部的方向错误，不能排除原图 front 标定误差。历史对齐审计显示 `maps/param/front.npy` 的图像轴角约 85.59°，而 GLB 规则 front 为 90°；同一 front seg 内，旧 front 标定的 mesh 命中像素为 22,385，GLB 标定仅 9,068。说明 front 语义守卫使用的投影与侧视重建头模并未完全共坐标。

## 量化证据

固定 v32 头模和长度证据后，左侧最大缺口约 9,388 个中心线像素。其投影范围内有 616 个候选根：

| 结果 | 数量 |
|---|---:|
| 局部积分达到长度预算 | 72 |
| 被 front 原图非头发语义否决 | 430 |
| 没有未截断长度证据 | 114 |

也就是说，约 70% 的候选不是因为 mesh 碰撞失败，而是因为 left 生成区域与 front 真值发生语义冲突；另有约 18% 缺少可审计的长度证据。关闭侧视共同否决后，后侧明显改善，但左侧缺口仍约 36%，符合“side 先验放宽不能消除 front 冲突”的预期。

## 处理含义

不能通过关闭 front 守卫、简单增加左侧根点或继续放宽长度预算来根治。正确方向是先建立左侧候选与 front 的可见性/遮挡对应关系，并将 side 证据改为软评分；只有能证明候选位于 front 头部遮挡之后、且能减少左侧缺口并保持方向连续时，才允许接受。否则它只能作为 FLUX 先验，不能覆盖原始 front 真值。
